# Tasks

**Rules for every code group.** Write the test, run it, confirm it fails, then change the code. Do one mutation check per behaviour: break the code on purpose, confirm one test fails, revert. After each group, re-pin `tests/test_clean_base_tripwire.py` by test IDs: diff the collected IDs against the last pin, because per-file counts miss replaced cases. Keep every digest pin and golden snapshot from group 1 byte-identical in groups 2 to 6. Commit with `uv run --no-sync git ...` (plain `git commit` cannot find pre-commit). Do not commit while another agent still edits the worktree.

**Order.** Group 0 is done except the data-store copy. Then groups 1, 2, 3 and 4 run in sequence: they share `ocr_routing.py`, `page_routing.py` and the identity builders. After group 4, groups 5 and 6 can run in parallel by two subagents (5 owns `integrations/part_registry.py`, `compose.py`, `compose_settings.py` and `config/`; 6 owns `transports/api/`, `web/src/`, `compose_runtimes.py`, `core/ingestion/` derivations and the drift tests). Task 6.1 touches only `compose_runtimes.py` and its tests, so it can also run in parallel with groups 2 to 4. Re-pin the tripwire once after parallel groups both finish. Group 7 starts after groups 5 and 6 and after the operator approves the extra. In group 8, tasks 8.1 to 8.4 can run in parallel on separate files.
